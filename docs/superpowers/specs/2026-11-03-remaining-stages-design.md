## Объём и порядок

оплату, возвраты, администрирование, документацию API, логирование, контейнеризацию,

## Конфигурация Stripe

Добавить STRIPE_ENABLED, по умолчанию false. При false приложение запускается
без ключей, бесплатные билеты работают, операции, требующие Stripe, возвращают
HTTP 503 с английским сообщением. При true обязательны STRIPE_SECRET_KEY и
STRIPE_WEBHOOK_SECRET. Не включать фиктивную успешную оплату при отключении.
В .env.example и README описать получение ключей test mode, отдельный signing
secret для локального stripe listen и серверного webhook, включение интеграции
и FRONTEND_URL. Реальных секретов в исходниках нет.

## Жизненный цикл брони

BookingsExpiryService каждую минуту обрабатывает до 100 просроченных PENDING
броней. Условный переход PENDING → EXPIRED и возврат мест происходят в одной
транзакции. Ошибка одной записи не останавливает пакет. Конкурирующие процессы
возвращают места только один раз. Порядок блокировок: мероприятие, затем бронь.

После истечения или отмены закрывать открытые Checkout-сессии вне транзакции.
Сохранять возможность повторной попытки закрытия сессии при сетевой ошибке.
Отключённый Stripe не мешает освобождать места.

POST /bookings/:id/pay проверяет владельца, статус, срок брони и доступность
мероприятия. Просроченные брони возвращают BOOKING_EXPIRED, остальные
не-PENDING — BOOKING_NOT_PENDING. Бесплатная бронь атомарно переходит в PAID,
получает paidAt и уникальный ticketCode вида SL-XXXX-XXXX; ответ содержит
относительный checkoutUrl по контракту. Генерация использует crypto.randomInt.

## Checkout и вебхуки

Выделить Stripe-провайдер, сервис платежей и публичный webhook-контроллер.
Checkout использует зафиксированные цену, валюту и количество, email покупателя,
metadata bookingId и маршруты возврата из FRONTEND_URL. Повторные и параллельные
запросы должны переиспользовать одну платёжную попытку: устойчивый ключ
идемпотентности Stripe и уникальность записи сессии в БД. При новой попытке
после закрытой сессии использовать новый, сохранённый идентификатор попытки.
Изменения модели и миграция допустимы, если нужны для фиксации попытки до
внешнего запроса и восстановления после сбоя.

Все внешние вызовы Stripe выполняются вне транзакций БД. После ответа Stripe
повторно проверить возможность оплаты; созданную для отменённой или истёкшей
брони сессию закрыть. Учитывать webhook, пришедший до сохранения ответа Checkout:
событие должно быть повторяемым, а не потерянным.

Webhook принимает исходные байты, проверяет Stripe-Signature и освобождён от
JWT и rate limiting. Неверная подпись — 400. Запись ProcessedWebhookEvent и
эффекты события коммитятся вместе. Повторная доставка не изменяет результат.
Обработать checkout.session.completed, checkout.session.expired и charge.refunded;
неизвестные события подтвердить. Проверять принадлежность платежа, сумму и валюту.
PAID подтверждается только успешным платёжным событием, без доверия к редиректу.

Поздняя оплата истёкшей/отменённой брони возвращается идемпотентно. Оплата после
expiresAt до прохода cron также считается поздней. Повторное событие об уже
подтверждённом платеже не вызывает возврат. Обязательства возврата должны
оставаться видимыми в БД после коммита и сбоя внешнего вызова, чтобы повторный
webhook или фоновый обработчик завершил работу.

## Возвраты

Для пользовательской отмены PAID проверять, что до начала мероприятия строго
больше REFUND_WINDOW_HOURS. Иначе REFUND_WINDOW_CLOSED. Бесплатные брони
возвращаются без Stripe. Для платных сначала идемпотентный Stripe refund,
затем транзакция PAID → REFUNDED, cancelledAt, возврат мест и обновление Payment.
Конкурирующие запросы и повтор после сбоя БД не дублируют возврат или места.
Единый ключ возврата платежа используется всеми инициаторами возврата.

Cron каждую минуту обрабатывает до 50 PAID-броней отменённых мероприятий,
используя тот же механизм без проверки окна возврата. Отдельно подбираются
незавершённые поздние возвраты и задачи закрытия сессий. Ошибки логируются с id
и не останавливают обработку остальных записей. charge.refunded учитывает
полный возврат и не считает частичный возврат полным.

## Администрирование

GET /admin/users доступен ADMIN: пагинация, поиск email/name без учёта регистра,
createdAt asc, публичное представление User. PATCH /admin/users/:id/role
валидирует UUID и Role, запрещает смену собственной роли с кодом
CANNOT_CHANGE_OWN_ROLE, отсутствующий пользователь — 404. Ответы не содержат
passwordHash. Сверить поведение с существующим frontend.

Проверить healthcheck, shutdown hooks и обработку ошибок по контракту.

Добавить backend Dockerfile и .dockerignore, сборку Prisma client, миграции при
старте и рабочий путь запуска. Согласовать production compose с отключаемым
Stripe. CI запускает unit/e2e с PostgreSQL до сборки и деплоя; конфигурация
тестов не использует реальные Stripe-ключи. Обновить README: локальный запуск,
тесты, seed, Stripe, переменные сервера и GitHub Secrets, команды деплоя.
